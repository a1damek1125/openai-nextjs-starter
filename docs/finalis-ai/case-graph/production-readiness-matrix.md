## Summary — verified vs. designed, honestly

**Verified (Implemented in the scaffold, proven by 160 passing tests including the
23-step E2E):** the Case Graph's *logic core* — Case/Party/MissingItem/Promise/
EvidenceReference dataclasses, the full 17-state machine with legal/illegal/global-edge
and final-state-override semantics, the hash-chained append-only audit log with tamper
detection, the Completion Loop tick (promise evaluation, stuck sweep, NBA selection,
gate ruling, anti-spam follow-up, duplicate suppression, never-drop invariant),
the four-outcome ActionGate with a conservative default, service-level tenant
isolation (both directions tested), and the LGGT Phase-1 placeholder
(protocol + NullAdapter + Certificate with `audit_id`).

**Designed only (zero serving code):** every REST endpoint, authentication and
authorization (including the role check the final-state override needs), persistence
and Postgres RLS, the Task and Action and DecisionBrief *entities* (today: dicts,
gate-decision audit events, and a brief-shaped audit event respectively), the human
approval workflow (queue + decision endpoint), real outbound channels, a scheduled
loop runner, and the case-graph additions to `openapi.finalis.yaml`.

**The two claims to be strict about:** (1) "never drop a case" is proven as a
*per-tick invariant*, not as an operating guarantee — no scheduler exists to run the
tick in production, and duplicate-prevention state is in-memory, so a restart both
stops the loop and forgets recent asks; (2) tenant isolation is real but shallow —
two tested service checks, with the database-level guarantee (RLS) still on paper.
Both are P0 rows above. Nothing in this module is enterprise ready; everything in it
is an honest, tested specification of what the enterprise version must do.
