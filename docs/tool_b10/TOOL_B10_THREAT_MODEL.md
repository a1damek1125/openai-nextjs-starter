# TOOL-B10 Threat Model

This document maps the threats the FINALIS Context Governance kernel is designed to
withstand to the specific mechanism in the code that mitigates each. Every mitigation
below is realized in `tools/context_governance/` and is deterministic and
fail-closed. The kernel governs the **context** that planners, reasoning models and
tools consume; it does not itself execute the downstream work.

| # | Threat | Mitigating mechanism (module.function) | How it is contained |
|---|--------|-----------------------------------------|---------------------|
| 1 | **Prompt injection** — external text tries to steer the model or smuggle instructions. | `evidence.evidence_record` (channel `INFORMATION`, default taint `EXTERNAL`); `model.taint_join` / `evidence.propagate_taint`; `evidence.taint_findings`; `model.TAINT_LEVELS` up to `SUSPECTED_INJECTION`/`QUARANTINED`. | External content is confined to the INFORMATION channel and taint-tracked; a claim carrying `SUSPECTED_INJECTION`/`QUARANTINED` taint is flagged P0 (critical) / P1 and cannot cleanly satisfy a requirement — injected instructions never become authority. `model.taint_join` treats an **unrecognized** taint label as most-severe (fail-closed), so a fabricated label cannot launder taint to `UNTAINTED`. |
| 2 | **Tool poisoning** — a compromised tool emits manipulated output. | `model.TAINT_LEVELS` includes `TOOL_OUTPUT`; `evidence.propagate_taint` joins it forward; `evidence.taint_findings`; boundary (`boundary.classify_effect`) forbids `TOOL_EXECUTION`/`MCP_CALL`/`A2A_CALL`. | Tool output is a tainted INFORMATION-channel input, never an authority; the kernel additionally executes no tool itself, so a poisoned tool cannot be invoked through it. |
| 3 | **Memory poisoning** — a malicious "lesson" is written back and later trusted. | `evidence.memory_candidate` (starts `QUARANTINED`, `auto_admitted=False`); `evidence.memory_findings`; `boundary.FORBIDDEN_EFFECTS` includes `MEMORY_WRITEBACK`. | Writeback candidates are quarantined and cannot self-release even on successful work; an auto-admission is a P0. The boundary forbids the kernel from performing a memory writeback at all. |
| 4 | **Cross-tenant / cross-purpose / cross-account context flow** — context leaks across isolation boundaries. | `entitlement.check_entitlement` (tenant / principal / provider account / purpose / operation class must all match, each mismatch P0); `entitlement.cache_key` + `cache_reusable` (exact scope+vector match required). | Entitlement precedes retrieval and any scope mismatch blocks; cache reuse is keyed on tenant+principal+account+purpose+operation+vector so cross-scope reuse is structurally impossible. |
| 5 | **Authority inference from documents** — a document is read as granting permission/approval. | `evidence.authority_air_gap` (any record asserting authority whose channel is not `AUTHORITY` → P0; a missing channel fails closed); `capsule.check_capsule` (`informs_only`: `informs_not_authorizes` true and no body key hinting at authority/grant/approval/permission); `capsule.ALLOWED_BODY_KEYS` (closed body shape). | The air-gap rejects any record that asserts authority without genuinely being in the AUTHORITY channel — a record with a missing or unknown channel is rejected too — and the capsule structurally cannot carry an authority grant (the closed allowlist blocks such keys; the authority-key scan is defence in depth) — the output informs, never authorizes. |
| 6 | **TOCTOU / staleness** — inputs change between snapshot and consumption. | `entitlement.snapshot` + `version_vector` + `issue_lease`; `entitlement.revalidate` (delta classification + verdict); `entitlement.toctou_findings`; `compile.consumption_receipt` (`lease_valid`). | The lease binds an exact vector; revalidation blocks on expiry, on any material delta, or on an UNKNOWN critical delta (`_classify_delta` → `UNKNOWN` → `BLOCKED`); a stale lease at consumption yields `TOCTOU_REVALIDATION_FAILED` (P0). |
| 7 | **Common-mode false corroboration** — mirrored / shared-model / shared-provider sources are double-counted as independent agreement. | `evidence.common_mode_graph`; `evidence.independence_class`; `requirements._independent_producers` + `evaluate_requirement` (`min_independent` floor); `requirements.requirement_findings` (`COMMON_MODE_SUPPORT_INSUFFICIENT`). | Sources sharing an origin, extraction model or provider collapse to one producer; an atom whose support does not meet the independence floor is `common_mode_short` and flagged, so mirrors do not multiply independence. |
| 8 | **Provider truncation** — the model silently receives fewer bytes than rendered. | `compile.render_abi` (deterministic byte length); `compile.consumption_receipt` (`NONE`/`DETECTED`/`UNKNOWN`); `compile.receipt_findings`. | The receipt binds the exact rendered byte length; a mismatch is `PROVIDER_TRUNCATION_DETECTED` (P0) and a missing provider length is `PROVIDER_TRUNCATION_UNKNOWN` (P1) — the kernel cannot prove no truncation, so it fails closed. |
| 9 | **Compaction claim-loss** — summarization drops or flips a critical claim, or launders its taint. | `compile.compaction` (checks polarity, four-valued state, quantity/unit, scope, provenance **and taint** over critical claims); `compile.compaction_findings`. | Any lost or altered critical invariant produces a specific P0 (`COMPRESSION_CLAIM_LOSS`, `COMPRESSION_NEGATION_CHANGED`, `COMPRESSION_CONTRADICTION_LOST`, `COMPRESSION_QUANTITY_CHANGED`, `COMPRESSION_SCOPE_CHANGED`, `COMPRESSION_PROVENANCE_LOST`, `COMPRESSION_TAINT_STRIPPED`); compaction is a semantic contract, not byte reduction, and cannot strip taint off a critical claim. |
| 10 | **False consensus on merge** — conflicting hypotheses are collapsed into agreement. | `compile.merge_branches` (preserves conflicts, `critical_conflicts`); `compile.merge_findings` (`MERGE_CRITICAL_CONFLICT` P0). | A critical atom supported on one branch and refuted on another stays a preserved conflict; the merge never fabricates consensus and never amplifies authority. |
| 11 | **Capsule forgery / self-certification** — a tampered capsule, a smuggled body field, or a generator vouching for itself. | `capsule.certify_capsule` (`generator_id`, `body_hash`); `capsule._capsule_roots` (`BODY` root over the **entire** canonical body); `capsule.ALLOWED_BODY_KEYS` + `capsule._disallowed_body_keys` (closed body shape); `capsule.check_capsule` (independent re-derivation, `body_hash_ok`, `well_formed`/`disallowed_keys`, `checker_id != generator_id`); `capsule.capsule_findings`; `capsule.replay_twin`. | The byte-independent checker re-derives every root from the body alone; the `BODY` root binds every field (including `support_bases` and `compiler_version`), so no field can be swapped post-certification, and a smuggled out-of-allowlist key fails `well_formed`. A root/body-hash mismatch or disallowed key is `CAPSULE_CERTIFICATE_INVALID` (P0), a generator==checker is `GENERATOR_SELF_CERTIFICATION` (P0), and a nondeterministic rebuild is `CAPSULE_REPLAY_DIVERGED` (P0). |
| 12 | **Secret / provider-token exfiltration** — credentials leak into context or a view. | `capsule._scan_secret_free` + `check_capsule` (`secret_free`); `compile.compile_view` (`_FORBIDDEN_FIELDS`, `leaked_forbidden`); `compile.view_findings`; `boundary.FORBIDDEN_EFFECTS` includes `SECRET_EMIT`/`CREDENTIAL_READ`. | The capsule body is scanned for secret markers in keys **and in string values** (`_SECRET_VALUE_MARKERS`, e.g. `sk-`, `bearer `, `-----begin`) before sealing (`PROVIDER_TOKEN_IN_CAPSULE` P0), so a secret hidden under an innocuous key is still caught; each view drops forbidden fields (`VIEW_LEAKAGE` P0); the boundary forbids reading credentials or emitting secrets. |
| 13 | **Information-flow leakage across sensitivity** — a high-sensitivity input changes a low-privilege view. | `compile.compile_view` (least-privilege `_VIEW_GRANTS` per consumer class); `compile.noninterference`; `compile.view_findings` (`NONINTERFERENCE_FAILED` P0). | Each consumer class gets only its granted fields; noninterference requires the low view's bytes to be identical under two high-input worlds — a difference is a P0. |
| 14 | **Privacy budget gaming** — abundance on one privacy axis pays for exhaustion on another. | `compile.privacy_budget`; `compile.privacy_exposure` (per-axis, non-compensatory); `compile.privacy_findings`. | Each axis is checked independently; a single overrun fails the whole budget (`PRIVACY_EXPOSURE_EXCEEDED` P0) irrespective of slack elsewhere, and an exposure on an **unknown** axis has no budget and fails closed (overrun with limit 0) rather than being silently ignored. |
| 15 | **Silent statistical over-claiming** — a broken statistical guarantee is assumed to hold. | `requirements.conformal_interval` (shift guard disables the guarantee); `requirements.statistics_findings`; `requirements.anytime_decision` / `eprocess_wealth` (optional-stopping-valid). | A detected distribution shift breaks exchangeability and disables the conformal guarantee (`DISTRIBUTION_SHIFT_DETECTED` P1); an inactive guarantee is surfaced (`CONFORMAL_GUARANTEE_DISABLED` P2) — never silently assumed. |
| 16 | **Budget-driven eviction of safety-critical context** — a token budget drops a mandatory claim. | `requirements.reserve_mandatory`; `requirements.robust_select` (reserved pre-committed); `requirements.selection_findings`; `requirements.voi_retrieval`. | Mandatory bases are reserved before selection and never dropped; over-budget reservation is `CONTEXT_BUDGET_INSUFFICIENT` (P0) and an evicted reserved claim is `MANDATORY_RETRIEVAL_STOPPED` (P0). |
| 17 | **Source degradation / adversarial dropout** — the selected set collapses when a source turns out stale or revoked. | `requirements.robust_select` with `scenarios` (`_robust_value` = worst-case coverage over a plausibility set). | Selection maximizes worst-case coverage over scenarios that each drop some claims, so the chosen set is robust to a source being revoked or going stale. |
| 18 | **Incomplete trusted computing base** — a guarantee is asserted while a trusted component is absent. | `capsule.tcb_manifest` (enumerates `TCB_COMPONENTS`, `complete` flag). | A missing component makes the TCB incomplete (fail-closed), so the guarantee is not asserted over a hollow trust base. |

## Residual risk is carried explicitly

`capsule.risk_envelope` attaches the worst case to the capsule — `taint_max`,
`unresolved_conflicts`, `common_mode_atoms`, whether the statistical guarantee is
active, whether privacy is within budget, and the truncation state — so a downstream
consumer always sees residual risk instead of an implicit clean bill.

## Out of scope by design

The kernel does not execute downstream work, call live tools/MCP/A2A servers,
contact external transparency services, or run external SMT solvers; those are
optional adapters, never required by the reference kernel. The mitigations above
govern the **context** handed to such systems, not their internal behavior.
